## 1. Style preset: *Phosphor instrument*

A bring-up bench at night: dark metal, one lit surface, everything else quiet.
The screen is a tool that is looked at for hours, so contrast is spent on
information, never on chrome.

| Token | Value | Use |
|---|---|---|
| `--void` | `#07090B` | page |
| `--panel` | `#0C1013` | rails, top bar |
| `--panel-2` | `#11161A` | raised rows, hover |
| `--line` | `rgba(255,255,255,.08)` | hairline rules, 1px |
| `--text` | `#E6EDF3` | primary text |
| `--dim` | `#9AA7B2` | body copy, second level |
| `--faint` | `#68737D` | labels, metadata, line numbers |
| `--mint` | `#7FE3BC` | the one accent: live node, active step, primary action |
| `--amber` | `#F2B33D` | warning, and the only colour on the boot image node |
| `--alarm` | `#FF6B6B` | error, dead node, the step that kills the boot |

- **Type**: `IBM Plex Mono` for everything that is code, paths, numbers and
  labels — this is a tool about a text file, so the mono face is the voice.
  `Inter` for sentences. Seven sizes only: 11 / 12 / 13 / 16 / 20 / 28 / 40.
- **Rules**: 1px hairlines, 4px radius maximum, no drop shadows except the
  findings rail (a tool surface that sits above the canvas). No gradients. No
  icons where a word fits.
- **Colour discipline**: mint means "alive / current". Amber means "this will
  hurt". Alarm means "this kills the boot". A screen may show all three, but
  each node carries exactly one.
- **Motion**: the replay advances at 520 ms per step; the active node fades in
  over 180 ms; the timeline cursor eases at 0.12 per frame. Everything stops
  under `prefers-reduced-motion`, and the replay becomes a step control.

## 2. Ruler — what "good" looks like here

| Reference | Link | What we borrow |
|---|---|---|
| QNX Momentics **System Builder** (the incumbent) | QNX SDP docs, *System Builder User's Guide* | The mental model: an image is a tree of files plus a boot script. We keep the model and drop the 2005 chrome. |
| **Linear** | https://linear.app | Restraint: one accent, dense information that still breathes, 1px rules instead of boxes. |
| **Raycast** | https://www.raycast.com | A single surface that feels inevitable; keyboard reachable, no modal detours. |
| **Sentry — trace waterfall** | https://sentry.io | The closest cousin to our replay: time as a horizontal axis, each row a thing that starts, and colour reserved for what went wrong. |
| **Chrome DevTools — Performance panel** | built into Chrome | The scrubber mental model: drag a cursor, the rest of the UI follows the cursor. |
| **Vercel dashboard** | https://vercel.com | Status colour discipline: green/amber/red used only for state, never for decoration; monospace numerals. |

Six references, five of them shipped tools a QNX engineer already knows. The
incumbent is the benchmark we must beat, not a style source.

## 3. One memory point

**The boot is a timeline you can scrub, and one moment on it is red.**

Not a linter list, not a graph: a horizontal rail where the image comes alive
step by step, and the step that kills the console is marked in alarm red. A
judge who remembers one frame remembers the red step on a green rail.

Everything else on the screen is allowed to be quiet so that this survives a
three-second glance.

## 4. Main screen specification

Virtual canvas 1440×900, DPR capped at 2.

- **Top bar** 56 px: wordmark `BOOTPRINT` in 13 px mono, letter-spaced 0.18em;
  sample selector (a native select, 13 px); `Open .build` button; right side:
  three pills (error / warning / info) with counts in 13 px mono; `Replay`
  button 32 px high.
- **Left rail** 248 px, full height under the bar: image contents. Section
  headers 11 px mono uppercase `--faint`. Rows 26 px: name 13 px mono, kind
  badge 11 px. The boot image and the startup script sit at the top with an
  amber left border 2 px; everything else is a flat list grouped by directory.
- **Centre** fluid: three stacked regions with 1px separators.
  - **Replay rail** 92 px: a 1px track with one tick per step (8 px apart, min
    6 px), a 2 px mint progress fill, and a movable cursor. Above the track, the
    current step's label in 16 px; below it, the step's source line in 11 px
    mono `--faint`. Error steps carry a 6 px alarm dot above the track.
  - **Topology** 320 px tall, SVG, viewBox `0 0 1000 320`: kernel node at
    x=90; process nodes in boot order at 150 px spacing, 44 px chips, 13 px
    mono; device chips 22 px below the node that publishes them; edges are 1px
    lines with a 3 px arrowhead. Live = mint border, pending = `--line`,
    error = alarm.
  - **Source** remaining height, scrollable: line numbers 11 px mono `--faint`,
    code 13 px mono, 22 px row height. The active line has a 2 px mint left
    border; a line with a finding has a 2 px alarm or amber left border and a
    faint tinted row.
- **Right rail** 392 px: findings. Header 40 px with the count. Each finding:
  76 px, title 13 px, detail 13 px `--dim` max 2 lines, footer 11 px mono with
  `line 12` and the rule id. Hover raises to `--panel-2`; the selected finding
  has a 2 px mint left border.
- **Status bar** 32 px: entries, processes, target arch, and `offline · no data
  leaves this page` in 11 px mono `--faint`.
- **Empty state**: the centre becomes a 480 px drop zone — one sentence, one
  button, no illustration.
- **Error state**: parse errors appear as findings of severity `error` with the
  parser's own message; the source pane never goes blank.
